# Review of 2026-11-15

Four outside reports were checked against `main` at 0e5687d: containers (C), video (V), platform (P) and audio (A). Every claim was
read in the code with its callers. The video decoders (VC-1, Microsoft MPEG-4, WMV7/8, IntraX8) are ports of FFmpeg's and were also
checked against FFmpeg's source: where FFamp does exactly what FFmpeg does, on purpose for bit-exact output, the claim is not a bug.

How a claim was judged:

- REAL: a crash, a trap in the undefined-behaviour build (`tests/fuzz/build.sh`), a memory blow-up or hang out of proportion to the
  file, a data race, or wrong output on a valid or plausibly damaged file.
- NOT A BUG: the claim is wrong (the check exists, the code does something else), the behaviour is FFmpeg's on purpose, or only absurd
  values reach it and the only effect is odd numbers for that same file. The library is built with `-fwrapv`, so signed wrap-around is
  defined; `std::llround` out of range and `std::string(nullptr, 0)` do not trap (checked with the sanitizer build).
- UNSURE: real behaviour that needs a design decision.

Checks named in the Test column are `ffamp fixcheck <name>` (suite 88_fixes) unless they name a file; files under
`tests/fixtures/fuzz/open/` are replayed by suite 85_fuzz, also with undefined-behaviour checks. Each check fails without its fix.

## Real bugs by severity

Memory and races:

1. A1: WMA 1/2 with a tiny block size, 8 KB file to 2 GB (fixed in 5ceca71).
2. C7: AVI index entries repeating one chunk, 2 MB file to 2.3 GB, PCM and the MP3/AC-3 scan (5ceca71).
3. V1: the picture worker pool could run a row twice and return before the work finished (d87da9e).
4. P2: capture runtime-error notification against a freed recorder (d87da9e).
5. C6: Xiph lace sizes wrapping on 32-bit `size_t` (5ceca71; latent, no 32-bit build today).

Undefined behaviour:

6. C1: negative shift in the AVI H.264 order fields (5ceca71).

Wrong output:

7. P9: the first GOP lost when the sync table omits sample 1 (d87da9e).
8. P8: colour labels of frames without a matrix label ignored before scaling (d87da9e).
9. P11: MP4 sample gaps over 2^32 ticks (a2d27c5).
10. P14: Matroska tracks after the 126th (a2d27c5).
11. C14: track length and frame rate for tracks entirely before time 0 (5ceca71).
12. P18: monochrome AV1 bit-depth change (d87da9e).

Minor:

13. P7: a second `CaptureRecorder::finish()` after a failure returned true (d87da9e).

Not proven by a test in the suite: C6 (64-bit `size_t` cannot overflow here), V1 (a timing window; shown with a copy of `Crew` and a
forced pause), P2 (needs a camera fault), P18 (no 12-bit monochrome AV1 encoder here). V6 is left for a decision on the API.
